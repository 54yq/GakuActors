# GakuActors

独立的 GakuLoader 场景人物管理插件，提供人物目录、头身组合预设和场景人物名单。无需修改或依赖 GakuMotion。

当前版本为 **`0.1.3-recovery` 保护版**。`0.1.2-dev` 实测连续六次加入失败，并出现原场景人物消失的问题。保护版保留读取目录、编辑与保存预设，关闭新增、移除和移动人物。危险的全局缓存加载与未确认实例的销毁回滚代码已移除；没有可在界面开启的实验加载开关。

启动阶段保持休眠，仅在实际角色所属场景与活动场景共同确认是拍摄或 Live 时开放。进入后需手动点击“读取游戏目录”；不在启动、主页、更衣室等页面自动扫描，也不在失败后自动重试。

## 当前版本

- 独立 `GakuActors.dll`，在 GakuLoader 中有自己的面板和人物预设弹窗。默认快捷键为 **Ctrl+J**。
- 通过游戏已加载的 `CharacterMaster`、`CostumeMaster`、`CostumeHeadMaster` 读取人物、服装、头部和默认搭配。目录读取只发生在 Unity 主线程，不在 UI 线程加载游戏对象。
- 尝试读取原生老师、眼镜老师和三类训练员描述。接口不存在时跳过对应条目。若能从原生描述读取完整身体、脸和头发资源，可另存为自定义组合。
- 保存自定义人物预设，允许独立选择身体与头部，支持显示其他人物的选项或填写已知的身体／脸／头发资源。跨人物组合的骨架、颈部、表情和物理兼容性需实测。
- 预设保存到宿主分配的 `Configs/gakuactors/actor_presets.json`。文件损坏时保留原文件，禁止继续覆盖。
- 场景人物列表只读；保护版不创建、销毁、隐藏或移动场景人物。

## 加载状态

真实日志已确认读出 25 个人物、580 条身体服装记录、427 条头部记录。目录记录及身体／脸／头发资源定义可读取，均不代表对应模型已导入场景。

`0.1.2-dev` 调用共享 `UpdateCacheActorAsync` 后，六次都在解析任务返回值时报告“加载结果不包含可确认的角色索引”；没有一次输出模型网格、材质、骨骼或 `Spawn model READY` 证据。旧版异常路径还会在未确认新实例归属时调用 `TryDestroyActor`，不能保证原场景人物安全。缓存复用／逐出与错误回滚对本次消失的具体贡献尚不能仅凭日志确定。

保护版不再走上述路径。后续需要先确认独立实例分配及原生构建的完整契约，证明既有角色集合不会被复用或破坏，再恢复加入人物功能。主动作同步、原生物理和 GakuMotion 扫描识别均未通过验收。

游戏由用户启动和退出；安装仅在游戏进程退出后替换本插件 DLL，保留其他插件和用户预设。此保护版不能恢复当前进程中已消失的角色；应退出拍摄重进，必要时由用户重启游戏。

## 构建与验证

需要 Windows x64、MSVC C++20 和 Windows SDK；Dear ImGui、nlohmann/json 和宿主 C ABI 头文件已随源码包含。

```powershell
./build.ps1 -Target All -PortableVisualStudio '<MSVC 根目录>' -WindowsSdkRoot '<Windows SDK 根目录>'
```

产物为 `build/GakuActors.dll`。合成测试在隔离的 `build/test-temp` 下检查预设校验、中文路径持久化、损坏文件保护、值类型调用边界、所有权拒绝和插件 ABI。脚本不会部署或控制游戏。

`preview/scene-actors.html` 是使用示例数据的交互设计稿，不连接游戏、不持久化到游戏配置，也不代表模型显示结果。
