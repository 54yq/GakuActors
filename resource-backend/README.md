# 学园资源下载器

独立的《学园偶像大师》资源浏览、按需下载和导出工具。导入一份 Octo 清单后，可以查看资源与依赖，从清单指定的官方 CDN 对象下载所选文件，导出 FBX 模型、PNG 贴图和 Unity `.anim` 动作。

当前版本：**0.1.0**。本机访问地址：**http://127.0.0.1:8776/**。

## 启动与停止

双击 `Start.cmd`，或在 PowerShell 执行 `./Start.ps1`。首次打开页面时如果正在启动，稍后刷新即可。停止时双击 `Stop.cmd`，或运行 `./Stop.ps1`。

本项目使用自己的进程、端口、Python 虚拟环境、工具副本及 `data/` 目录。正常运行不需要游戏安装目录，不连接 GakuActors 或 GakuMotion，也不调用已部署的 SCSP 下载器服务。

已为首次体验导入一份清单：来源目录版本 `705100`，清单 revision 为 `89`，共 **51,335** 条资源记录。导入时保存了清单副本；此后的浏览和下载不再读取它原来的位置。清单目录版本与内部 revision 是不同字段。

## 使用流程

1. 点击“导入清单”，选择 `octocacheevai` 文件，也可以导入本工具保存的 JSON 清单。加密清单会校验完整性后再启用；失败时保留原有目录。
2. 按“模型部件”“图片与贴图”“动作”等分类浏览，或输入资源名称中的片段。搜索支持多个空格分隔的词。
3. 勾选资源，点击“查看下载计划”。工具会递归加入清单声明的依赖，显示去重后的下载体积。缺失依赖时不继续导出。
4. 选择处理方式和本次下载上限，点击“开始处理”。任务逐个执行，有效缓存按大小和 MD5 校验后复用。
5. 在“任务与导出文件”展开任务，可以打开或保存结果。导出目录路径也会显示在任务下方。失败任务可以重试；旧任务和中间日志保留。

常用搜索示例：

| 目的 | 搜索词 |
|---|---|
| 咲季基础脸部 | `mdl_chr_hski-base-0000_face` |
| 咲季基础头发 | `mdl_chr_hski-base-0000_hair` |
| 咲季初始服装身体 | `mdl_chr_hski-cstm-0000_body` |
| 咲季服装图片 | `img_cos_hski-cstm-0000_body` |
| 原生动作 | `mot_all_chr_amao_idle-001_pose` |
| Live 动作 | `mot_live_chr_cmmn_all-001_00_in` |

## 输出格式

| 模式 | 输出 | 范围 |
|---|---|---|
| 自动导出 | 根据所选条目的分类导出 FBX、PNG 或 `.anim` | 分类基于资源命名；未知用途请用原始资源模式或显式指定类型 |
| 模型 | 每个选中源包中的模型根节点分别输出 FBX、材质贴图及模型报告 | 读取依赖，保留转换器能导出的骨架与权重；不自动装配完整角色 |
| 贴图 | PNG | 原始分辨率的 Texture2D 与 Sprite，不缩略或重新烘焙 |
| 动作 | Unity AnimationClip `.anim` 及 `.meta` | 从选中源包恢复片段，校对名称和数量；没有 VMD 转换 |
| 仅下载原始资源 | 解码后的 `.unity3d` 或原资源文件 | 同时复制清单声明的依赖；下载原件另外保存在内容寻址缓存中 |

脸部、头发、身体可以一起选择，但会按部件分别输出。模型导出使用 AssetStudioMod，动作恢复使用 AssetRipper。原生 `.anim` 仍需要相应骨架、Avatar 或游戏绑定约定；不保证可以直接套到任意模型上。

资源解析默认使用 `6000.0.77f1`。当前样例资源的版本字符串被置为 `0.0.0`，工具会在导出工作副本中补齐版本字段，下载原件保持不变。如果导入的资源属于其他 Unity 构建，请调整界面中的版本字段。

## 数据目录

```text
data/
  catalog.sqlite3            当前资源目录
  manifests/                 导入清单的原始副本
  cache/raw/                 按 MD5 保存的下载原件
  cache/decoded/             解码副本与 SHA-256 记录
  jobs/<任务 ID>/
    job.json                 任务状态
    plan.json                清单指纹、所选资源与依赖
    _work/                   版本补齐副本及外部工具日志
    exports/
      export-report.json     导出来源、处理范围和警告
      models/                FBX、配套贴图与模型报告
      textures/              独立 PNG
      animations/            原生动作
      bundles/               原始资源模式的结果
  logs/                      服务日志
```

本工具不会改写游戏缓存，不自动清空下载、失败任务或中间工程。动作恢复为 YAML 后可能明显膨胀：本次约 1.9 MiB 的 Live 包生成了约 105 MiB 的 `.anim`，因此要预留导出磁盘空间。

## 本次实际验证

2026-11-17，在独立环境中完成以下检查：

- 导入清单 51,335 条，验证资源搜索、依赖计划和清单 JSON 往返。
- 咲季基础脸、头发和身体导出 **3 个 FBX**，连同独立服装图片共生成 **23 个 PNG**。
- `mot_all_chr_amao_idle-001_pose` 恢复 **2 个 AnimationClip**，对应源包中的 `_b` 与 `_f` 片段。
- `mot_live_chr_cmmn_all-001_00_in` 恢复 **1 个约 105 MiB 的 `.anim`**。
- 原始资源下载与校验缓存复用；PNG 可由 Pillow 完整读取，FBX 文件头与动作 YAML 类型检查通过。

实际结果记录在 `data/integration-results.json`。早期兼容性失败也留在任务历史中；版本字段和单一脸部网格引用的导出处理随后已修复。未在 Blender、Unity 编辑器或游戏中进行画面和播放验收。

脸部样例的 MeshFilter 引用未能直接解析。只有在**同一源文件恰有一个 Mesh 和一个待关联 MeshRenderer**时，导出器才使用该网格补齐工作副本引用；处理会写入 `model-report.json`。这不恢复游戏的运行时脸部变形、Shader 或物理。

## 开发环境与测试

本机使用 Windows x64、Python 3.9.6 和 .NET Framework 4.8.1。模型导出工具要求 .NET Framework 4.7.2 或兼容版本。已安装的 `.venv/` 与 `tools/` 都位于本项目内。

重新建立 Python 环境：运行 `Setup.ps1`。脚本只改动本项目的虚拟环境并重建 FBX 辅助程序；需要本目录中已有 `tools/AssetStudio` 和 `tools/AssetRipper` 完整工具文件。若迁移机器，请同时携带这些工具，或按 [第三方说明](THIRD_PARTY_NOTICES.md) 准备对应工具。当前锁定依赖针对 Python 3.9 至 3.12，不把 `.venv` 当成可直接迁移的便携解释器。

```powershell
./.venv/Scripts/python.exe -m unittest -v test_core test_http
node --check web/app.js
./Build-Exporter.ps1
```

核心和 HTTP 测试使用合成清单、模拟下载和临时数据，覆盖损坏清单不覆盖当前目录、重复 ID、依赖环、资源与包 ID 分离、缓存损坏、大小校验、取消、原始导出依赖、本机来源校验及路径边界。`smoke_test.py` 用于实际资源的有限集成验证，正常使用不需要运行它。

## 首版边界

- 清单由用户导入，不自动获取最新版本，也不把已有清单当成服务器实时目录。
- 依赖关系以清单为准；游戏在运行时动态拼装或隐式加载的资源仍可能需要额外研究。
- 场景和音频可以浏览、按需下载；完整场景工程恢复和 WAV 转换不在首版范围内。
- 不做 VMD、PMX、角色自动装配、游戏 Shader 复刻、运行时物理或完整 Live 还原。
- 工具代码与第三方工具的许可不包含游戏资产使用许可。
