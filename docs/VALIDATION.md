# 第一版验证记录

版本：`0.1.2-dev`。本记录区分离线结果与未执行的游戏内验收。

## 真实目录与空角色问题

`0.1.1-dev` 的实机日志已确认进入支持场景后手动读出 25 个人物、580 条身体服装记录、427 条头部记录。记录数量不代表资产已加载。用户报告新增后模型没有显示；原实现忽略异步返回的构建结果，只检查控制器和场景位置，没有检查模型或开启原生渲染，也没有足够的请求／完成日志。无法从旧日志追认实际模型导入成功。

`0.1.2-dev` 改用游戏的完整缓存加载入口，优先 `CampusActorUtility.UpdateCacheActorAsync(description, initialRenderActive=true, ct)`，缺失时仅回退到完整 `CampusActorManager.UpdateCacheActorAsync`，不再手工分配索引并调用底层更新。任务结果和 `IsBuildSuccess` 必须成功，且身体／脸部、带顶点的蒙皮网格、材质、骨骼及原生渲染状态均有证据，才写入 owned 人物名单并输出 `Spawn model READY`。失败尝试回滚，仅操作本插件的独立身份。

模型分类与身份相互独立；保存到“花海咲季”等分类的预设可以引用 `nasr` 等模型。分类不作为拒绝模型组合的条件。高级资源列表此前只来自特殊人物工厂，普通服装现在在显式读目录后逐帧解析其原生描述。相同脸部但不同头发的组合分开显示，重复身体项合并，原始资源预设卡片显示实际资源名。

74 项合成检查包含空控制器、缺身体／脸、零顶点／材质／骨骼、未启用渲染的拒绝，以及分类无关性和头部组合去重。启动休眠回归与独立插件 ABI 同时保留。此版本尚未通过游戏内模型显示、动作同步或原生物理验收。

## 首次实机启动后的修正

用户报告装入初版后无法正常进入游戏。Loader 日志确认初版激活和导出解析完成，没有人物目录读取成功记录。源码确认初版在 runtime-ready 后自动访问 Master 并反复扫描场景，缺少拍摄／Live 准入门控；这是已确认的设计缺陷，尚不能据此断言某个原生调用就是卡住的唯一原因。

初版安装文件已保留为 `.dll.disabled`，其二进制和启动日志尾部另存 ignored `build/live-test-20261115/startup-regression/`。修正版增加实际角色所属场景＋活动场景准入、过期失效、离开场景休眠和显式目录读取。启动不自动扫描，读取失败不自动重试，目录阶段有 begin/end 日志。

修正版通过 60 项核心检查及真实插件帧泵回归：runtime-ready=true、IL2CPP 指针为空时连续运行 120 帧，并拒绝不支持页面的读目录和加人请求，不需要调用任何游戏 API。游戏启动／目录读取／加人仍需重新实测。

## 已执行

- MSVC 14.35、Windows x64、C++20、`/utf-8` 本地编译，生成独立 `GakuActors.dll`。
- 60 项核心检查通过：人物预设字段、非法／冲突组合、特殊人物接口白名单、中文路径读写、编辑与删除、损坏／重复 ID 文件拒绝覆盖、目录匹配、值类型 `runtime_invoke` 的 unbox 边界、异常返回、非本插件人物的移除拒绝，以及场景门控／过期／其他页面拒绝。
- 只加载本次编译的 `GakuActors.dll` 进行 C ABI 合成检查：版本／长度／空指针拒绝、失败时输出不变、独立插件标识、生命周期回调、无 actor tick 接管。
- 本地 Chromium 无界面预览：桌面和窄容器分别通过 9 项浏览器交互／布局检查，覆盖新建预设、保存、加入、重叠状态、移除、特殊人物筛选、老师选择和内容宽度。截图已目视检查。预览使用示例数据，不连接游戏。
- 本项目的修改仅提交到独立 `GakuActors` 仓库，没有修改或提交 `source-clock-fix` 源码；构建脚本没有部署步骤。实机测试由用户启动和退出游戏。

日志位于 ignored `build/`，不作为游戏内成功证据。

## 原生加载防护

- 仅在新鲜的拍摄／Live 场景准入有效时尝试创建，且必须有同场景参考角色。
- 创建前核对独立 ID setter、索引、创建、完成观察、取消和释放方法；不以方法名称或参数数量直接冒充完整签名。
- 创建任务使用独立取消源。场景变化时请求取消，等待原生任务结束再释放观察状态。
- 创建完成后检查控制器类型和场景归属，再登记实例。新增世界位置和朝向取请求时的参考角色。
- 移除只使用本插件生成的独立 ID；名单／UI 不持有托管指针。原生对象访问只发生在 Unity 线程。
- 界面需显式启用实验加载；读目录和保存预设不需要启用。

这些是代码边界和合成检查，不能替代下面的实机验收。
