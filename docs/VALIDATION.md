# 验证记录

版本：`0.1.3-recovery`。离线通过不代表游戏内模型加载成功。

## 2026-11-15 人物消失故障

用户在拍摄场景重新读取目录，重复点击加入后报告原场景人物全部消失。实机 `gakuloader.log` 中，本次会话记录：

- 目录读取成功：25 个人物、580 条身体服装记录、427 条头部记录。
- 六次请求同一预设，分类 `hume`，身体服装 `hume-cstm-0000`，头部 `costume_head_hume-cstm-0000`；原始模型名字段为空，走逻辑服装／头部描述。
- 六次均调用 `CampusActorUtility.UpdateCacheActorAsync(initialRenderActive=true)` 并启动原生任务。
- 六次均失败于“加载结果不包含可确认的角色索引”。没有模型部件／网格／材质／骨骼检查日志，没有 `Spawn model READY`。
- 最后出现离开表演场景／暂停扫描日志。不能仅由这条记录推断是用户离开页面还是角色回调失效。

源码确认两处问题：使用了包含缓存复用逻辑的共享更新入口；异常和取消路径在没有验证新实例 ID／索引／归属时，按生成的 uniqueId 调用 `TryDestroyActor`。生成 uniqueId 不足以证明缓存返回的是新实例。原日志没有被复用、销毁或逐出的具体实例 ID，因此不能追认身体／头部／骨骼成功加载，也不能精确归因每个原角色如何消失。

旧 DLL 和日志尾部保存在 ignored `build/live-test-20261115/incident-013/`，旧二进制 SHA256 为 `7E435B04F18E70DAF5A40946DCC4E0A7A90A6DB3A3604D0983ACCB8A6E661D25`。

## 保护版的变更

- 移除全局缓存创建、任务结果解析、销毁回滚、取消及场景对象清理路径。
- 关闭新增／移除／移动按钮，移除实验加载开关。底层三个操作也无条件拒绝，不能靠直接提交命令绕过界面。
- 场景扫描仅观察，不按扫描结果尝试清理原生缓存。离开场景和关闭插件也不销毁人物。
- 保留拍摄／Live 门控、显式目录读取、普通模型定义分帧解析、特殊人物描述和预设持久化。
- 不修改 GakuMotion，不覆盖用户人物预设。不在游戏运行时替换已加载的 DLL，也不由代理启动、关闭或重启游戏。

这是一版故障隔离补丁，不是独立实例加载修复。不能通过重新启用某个选项恢复实验加载。
