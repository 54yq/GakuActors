# Actors 桌面视觉交付

Web 原型用 CSS 流式布局，桌面版用 Slint 的显式布局约束。把 CSS 的颜色抄到控件上，只会改变配色。需要一起落实窗体壳层、控件尺寸、布局伸缩规则和不同数据状态。默认「人物与预设」必须单独评审，因为场景人物的截图无法说明默认页长什么样。

## 页面与设计基准

| 页面与状态 | 设计和检查范围 |
| --- | --- |
| 人物与预设 · 离线、有预设、首次运行 | [首页原型](../preview/actors-night-home.html) 支持 `?offline` 与 `?populated`。首次运行沿用离线结构，目录为空时显示读取入口。 |
| 场景人物 | [暗夜主题图](../preview/actors-night-theme.png)。核对人物列表、站位图、详情和操作柱。 |
| 场景与道具 · Live 与只读 | [道具页设计图](../preview/actors-night-props.png)。核对部件折叠、搜索、扫描状态、控制权限和备注。 |
| 预设编辑、舞台导入、资源库 | 沿用同一视觉规则，查看路径及操作仍然完整。 |
| 乐库 | 使用同一暗夜配色。检查搜索、主题对比度、播放栏和窄窗口控件。 |

先更新设计基准和对应运行状态，再修改 Slint 页面。共享的颜色、尺寸和页面组件在 `desktop-rust/src/night_theme.slint` 中维护，主工作区、资源库和独立乐库共同使用。数据投影继续走桌面程序的 `State::render`，场景控制继续经过插件权限和身份检查。

## 原生验收

运行项目根目录的 `Test-DesktopVisuals.ps1`。它使用 Cargo 编译原生测试，并把 PNG 及对照报告放在 `build/desktop-visual-review` 的新目录。已用本机工具链编译测试时，可传入 `-TestExe <测试程序>`。报告每次都生成独立目录，以免把上一轮图片当成本轮结果。

测试从默认窗体和真实数据投影切换各页面，并模拟点击品牌区域验证隐藏入口的倒计时与解锁，资产和人物来自 `tests/visual-fixtures/night-workspace.json`。视图使用实际发布代码里的 Slint 组件和软件渲染器。覆盖 1440×940 100%、1320×990 150%（物理尺寸 1980×1485）与 880×440 100%。步骤不启动游戏、资源服务或已安装客户端。原生系统标题栏与真实游戏内容需要另做实机检查。

交付前打开报告逐页对照。分别确认导航、标题、对齐、留白与空状态符合设计，再核对 150% 与紧凑窗口里的工具栏、滚动和禁用状态。截图缺页或渲染失败会使脚本失败。测试还检查首页导航和人物目录的实际宽度、页头按钮的垂直位置、无预设面板的绘制高度，以及最下面的导航入口在缩小窗口后是否仍然可见。视觉风格差异由评审确认。批准过的设计基准保留在 `preview`，不可用新实现截图自动替换。测试通过属于构建和渲染证据。
