# 人物与预设工作区

人物页采用人物列表、预设图库、预览与加入三栏。新建与编辑使用独立的模型选择页：身体与头部各一个图库，右栏确认已选图标并命名。保存成功以插件快照中的完整预设为准；收到实际写入结果后返回列表并选中对应 ID。保存失败时保留选择。

内置预设编辑时另存为自定义预设。原始身体／脸部／头发组合保留在高级入口。放置位置继续使用原生参考人物位置，界面明确提示可能重叠，并提供场景人物入口调整站位。

## 系统 icon 数据路径

1. 插件从原生目录读取身体和头部的 `GetThumbAssetName`。桌面快照保留图标名及头部的脸／发资源关系。
2. `load_part_thumbnail` 仅接受当前目录中的身体或头部 ID，转为已有主线程图片读取命令。桌面端无法通过此命令指定任意纹理名。
3. 桌面端优先读取插件预缓存的 PNG，命中时直接返回图库，不再排队请求游戏纹理。PNG 缓存保存来源 MD5、完整资源名和自身 SHA-256 校验。快速索引绑定当前游戏资源清单。
4. PNG 尚未预缓存时，再读取游戏已加载图片或本地 Octo 资源包，经校验后用 UnityPy 解出唯一匹配的 Sprite 或 Texture2D，并持久保存 PNG。普通界面读取保持离线。
5. 图片经有上限的 PNG 解码后交给 GDI，以保持比例的方式绘制。没有官方记录、未缓存或匹配不唯一时显示原因。

原始组合的头部 icon 必须同时匹配脸部和头发；相同头发下存在多个脸部时不能只按头发猜测。模型 icon 代表目录中的部件，不是自定义头身组合的完整三维渲染。

## 验证

`GakuActors.Desktop.exe --model-icons-prefetch <游戏目录> --download` 可按本机清单预缓存全部身体与头部 icon，并从官方补下载缺失图片。省略 `--download` 时只处理本机已有资源。缓存位于 `GakuLoader/Cache/gakuactors/model-icons/`，包含校验后的资源包、PNG、快速索引与完成报告；原有 Octo 数据库和资源文件保持原样。

2026-11-16 本机核验：共 1,011 个模型 icon，886 个复用游戏缓存，125 个从官方补下载（11,495,827 字节）。全部 PNG 已生成并通过完整性检查，缺失及失败均为 0。PNG 热读取无需加载 UnityPy，损坏的缓存会被拒绝。

- `build-people-ui.ps1 -Target Test`：布局边界、分页、目录筛选、保存结果匹配、图片关联、管道与 PNG 单元测试。
- `build-people-ui.ps1 -Target Release`：构建独立窗口。
- C++ core tests：校验新增部件图标命令的真实目录 ID 绑定、错误类型与越界输入。
- `--model-icon-check <游戏目录> <原生图标资源名>`：仅通过 CLI 验证实际缓存资源与嵌入式读取器。

本次在本机缓存实际提取并解码了 `img_cos_amao-cstm-0000_body` 和 `img_cos_costume_head_amao-cstm-0053_head`。没有通过模拟游戏快照启动界面，也尚未在真实游戏场景中验收新界面、保存及加入人物。
