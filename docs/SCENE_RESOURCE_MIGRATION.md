# 场景资源管理独立化清单

目标是在 GakuActors 内实现人物、道具和场景资源管理，运行时不要求安装 GakuMotion。两个插件可同时安装，但不能各自反复覆盖同一对象的状态。GakuLoader 仍是插件宿主。

## 已核对的原有能力

以下依据工作区 `source-clock-fix` 的 GakuMotion 源码（检查时提交 `1757f8e`）；这些能力尚未因此出现在 GakuActors 中。

| 分类 | 原有能力 | 实际边界与主要实现 |
| --- | --- | --- |
| 人物 | 场景角色的模型显隐 | `src/GkActorModelVisibility.hpp` 和 `src/GkModelRendererMask.hpp`；保存角色和每个渲染器的原始状态，并检查场景、实例和角色身份。不能通过停用整个人物对象代替。 |
| 道具 | 隐藏和恢复识别出的角色道具，包括麦克风 | `src/GkLiveActorProps.hpp`；仅识别角色下严格匹配的 `Root_X/Prop_X`，原逻辑还要求 Live 接管及其他安全条件。不是独立道具导入或摆放。 |
| 场景 | 背景显隐、纯色背景、颜色和光影开关 | `src/gui/GuiStagePage.hpp`、`src/GkStageManager.hpp`、`src/GkStageRuntime.hpp`；背景开关还涉及相机清除状态，光影开关涉及场景节点和角色阴影。 |
| 场景 | 扫描场景节点并单独切换 | `src/gui/GuiStagePage.hpp`；受自定义节点模式、父节点状态及碰撞节点保护限制。 |
| 场景 | 摄影背景载入时替换 | `src/gui/GuiStageLoadReplacement.hpp`；实验功能，选择在下次载入时生效，并非当前场景即时导入。原界面说明中庭舞台已有用户反馈，其他舞台灯光仍未完成。 |
| 人物 | 人物目录、预设、创建及本插件人物位置 | GakuActors 当前已有；目录条目不保证资源已下载或成功构建，创建属于实验功能。 |

## 迁移要求

1. 分别建立人物、道具、场景页面；GUI 只提交命令和显示快照，Unity 对象访问及修改都在 Unity 线程执行。现有仅拍摄／Live 准入、显式扫描和启动休眠的约束继续有效。
2. 每个可修改对象需要验证当前场景、实例身份和归属；保存修改前的状态，部分失败也要保留可恢复记录。切场景、人物更换和插件停用时须安全恢复，不能将旧命令作用于新场景。
3. 人物显隐需要连同逐渲染器的保存、回读、恢复和持续维护一起迁移，并处理原先不可见的模型；不能只调用一次 `SetRendererActive`。
4. 道具先迁移原有精确匹配的显隐能力，重新验证拍摄与 Live 各自的安全边界；原项目的 Live 接管条件不能在脱离 GakuMotion 时简单删除。自由导入、资源目录和位姿编辑属于新增能力，需要单独实现和实机验证。
5. 场景迁移包含节点扫描、碰撞保护、背景、相机、绿幕、光影及恢复；摄影舞台替换单独迁移并保留载入时生效和实验状态说明。
6. 同时运行两个插件时，要定义并验证对象状态的控制权及交接，避免一个插件恢复或持续重写另一个插件的修改。不能为了避免冲突而让独立插件依赖 GakuMotion 才能工作。
7. 对身份复用、初始隐藏、部分失败、场景切换、恢复、两个插件并存等情况做合成测试；构建通过不等于游戏内验证。真实游戏内验证由用户启动游戏进行。

GakuMotion 源码采用 MIT 许可；如迁移其代码，必须保留相应版权声明和许可，并记录来源。

## 独立化进度

已接入实验性资源扫描、人物渲染器显隐、精确匹配的角色道具显隐、场景节点树、相机纯色背景及摄影背景载入替换。扫描和控制只在拍摄／Live 场景显式启用；摄影替换钩子在摄影场景建立，加载器发现同址钩子占用时拒绝安装。场景树有 4096 节点扫描及 32 层展示上限，并锁定受保护或原本不可见的节点；道具仍限于指定结构。

布尔状态不能识别两个插件做出的相同写入。当前以检测到 GakuMotion 播放状态服务时尝试恢复并停用本插件显隐来保守避让；没有实现双方的细粒度控制权交接，因此不支持两者同时使用场景资源控制。未提供该服务的旧版或其他插件不能据此保证无冲突。所有新运行时路径尚未经过游戏内验证，合成测试不证明游戏内效果。
